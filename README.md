# منصة بناء «ميثاق ذرية حسين عمر شرواني»

أداة تفاعلية تعمل بالكامل داخل المتصفح (واجهة عربية RTL، بلا خادم وبلا تسجيل دخول) لمساعدة العائلة على **بناء مسودة ميثاق الصندوق العائلي**: اختيار البنود والبدائل وتعديلها، وإدارة القرارات، ومحاكاة الاشتراكات والقروض والأوقاف والأصول، وتجهيز الاجتماعات العائلية، وتصدير وثائق جاهزة للنقاش.

> الأسماء **قابلة للتعديل**: اسم العائلة (`family_name`، افتراضيًا «حسين عمر شرواني») واسم الميثاق (`charter_name`، افتراضيًا «ميثاق ذرية {{family_name}}») واسم الصندوق (`fund_name`)، وتتحدث تلقائيًا في العناوين والبنود والوثائق وصفحة التسجيل. وكل ما يمكن تعديله في المنصة قابل للتعديل: القيم، البنود، الفئات، الجداول، الأصول، المخاطر، الاجتماعات.

## تنبيه مهم

هذه المنصة **أداة إعداد مسودة ونقاش**. ما تُنتجه ليس وثيقة وقف رسمية ولا لائحة أساسية معتمدة، ولا يُغني عن الترخيص من الجهة المختصة والمراجعة النظامية والشرعية والمالية والمحاسبية. كل الأرقام في المحاكاة **تقديرية** وليست أموالًا محصّلة، والعوائد والعقارات غير مضمونة.

## ما تتضمنه

تسعة عشر قسمًا: لوحة المشروع · الهوية والرؤية والأهداف · نطاق الذرية والعضوية · الاشتراكات والالتزامات · الحقوق والعدالة والأولوية · القروض الحسنة · المساعدات والتكافل · مجلس الأمناء والحوكمة · الإدارة المالية والرقابة · الاستثمارات والأوقاف · سجل الأصول العقارية · الخطة المالية والمحاكاة (3 سيناريوهات + حاسبة عكسية + اختبار ضغط) · المخاطر واستمرارية الصندوق · الاجتماعات والتصويت والقرارات · مكتبة البنود والبدائل (142 بندًا عربيًا بالبدائل وإيجابياتها وسلبياتها) · مراجعة الميثاق واكتشاف النواقص (فجوات وتعارضات ومرجعية نظامية) · التقارير والتصدير (14 وثيقة) · عرض الميثاق للأسرة (شرح مبسط بشرائح) · تسجيل المشاركين والتزاماتهم (رابط تسجيل).

- **لا اعتماد تلقائي**: كل القرارات الجوهرية تبدأ «يحتاج مناقشة»، ولا يصير بند «معتمدًا» إلا بقرار منك أو بتسجيل قرار في اجتماع.
- **متغيرات ذكية**: النصوص تحوي `{{fund_name}}` ونحوها وتُستبدل بالقيم؛ وما لم يُدخل يظهر `[يُستكمل: …]` بدل الرمز الخام.
- **محرك عدالة وتعارضات**: ينبه عند التفريق بين المشتركين في الحقوق الأساسية، وعند تعارض القروض مع السيولة، وغيرها.
- **التصدير**: PDF (عبر الطباعة بخط عربي مضمّن)، DOCX، Markdown، وJSON لكامل المشروع.
- **الشرح المبسط**: شرائح عرض بملء الشاشة قبل بدء النقاش (أسهم الكيبورد، ورمز QR للتسجيل)، تُبنى من بيانات المشروع وتُخفي ما لم يُدخل، ولها نسخة مطبوعة (الوثيقة 14).
- **رابط التسجيل**: صفحة للمشاركين يسجلون فيها بياناتهم ثم يظهر لهم اختيار التزامهم ويُحفظ مباشرة في جدول Google Sheets الخاص بك (انظر «تسجيل المشاركين»).
- **التراجع والنسخ الاحتياطي**: تراجع/إعادة، نسخ تلقائية كل ساعة، نسخ يدوية، استنساخ مشروع للمقارنة، إعادة ضبط بتأكيد.

## التشغيل محليًا

المتطلبات: Node.js 20 أو أحدث (يُوصى بـ 22).

```bash
git clone https://github.com/husam550-ship-it/family-fund-charter
cd family-fund-charter      # كل أوامر npm تُشغَّل من داخل هذا المجلد
npm ci            # تثبيت الاعتماديات
npm run dev       # تشغيل للتطوير
npm test          # اختبارات الوحدات (محركات الحساب، العدالة، التعارضات، الحفظ، الوثائق، الشرائح، خدمة التسجيل)
npm run build     # فحص الأنواع ثم بناء الموقع في dist/
npm run preview   # معاينة ناتج البناء
```

### اختبارات القبول على متصفح فعلي

```bash
npm run build
npx playwright-core install chromium   # أو اضبط CHROMIUM_PATH على متصفح Chromium لديك
npm run e2e
```

يشغّل ملف `e2e/acceptance.mjs` خادمًا محليًا على **مسار فرعي** (`/family-fund-charter/`) يحاكي GitHub Pages، ثم يختبر سيناريوهات القبول: تعديل الاسم، تأثير المتغيرات، فئات المشتركين ومددهم، إضافة أصل عقاري، القروض ونقص السيولة، قرار الاجتماع والمحضر، الشرح المبسط، رابط التسجيل ومشاركون على خدمة التسجيل الحقيقية (بمحاكاة Google)، الحفظ والتراجع، التصدير/الاستيراد وملفات تالفة، النسخ الاحتياطية، PDF/DOCX/Markdown، الهاتف، ومسارات النشر. يحتاج أيضًا إلى `poppler-utils` (الأوامر `pdffonts` و`pdftotext` و`pdfinfo`) و`unzip` لفحص PDF وDOCX؛ وهي متوفرة على Linux وmacOS، وعلى ويندوز شغّل الأمر داخل WSL. وإن غابت فسيفشل اختبارا PDF وDOCX فقط ويمرّ الباقي.

## النشر على GitHub Pages (تشغيل الصفحات مباشرة)

الموقع ثابت (`base: './'` وتوجيه بالرمز `#`) فيعمل تحت أي اسم مستودع دون إعداد إضافي. الرابط بعد النشر:

```
https://<حسابك>.github.io/<اسم المستودع>/
```

1. ارفع الملفات إلى الفرع `main` (انظر أوامر git أعلاه).
2. **مرة واحدة فقط**: من المستودع على GitHub افتح **Settings ← Pages**، وتحت **Build and deployment** اختر **Source: GitHub Actions**. (دون هذه الخطوة تفشل خطوة `configure-pages` في السير، وهذا هو سبب أول فشل قد تراه.)
3. افتح تبويب **Actions** واختر سير **Deploy to GitHub Pages** ثم **Re-run all jobs** (أو ادفع أي تعديل جديد). يثبّت السير ويختبر ويبني ويفحص الخصوصية ثم ينشر، وعند نجاحه يظهر الرابط في الخطوة **deploy** وفي Settings ← Pages.
4. كل دفع لاحق إلى `main` ينشر تلقائيًا.

> ملاحظة: GitHub Pages للمستودعات الخاصة يتطلب خطة تدعمه. ولا يوجد في المنصة نفسها رمز دخول.

## تسجيل المشاركين والتزاماتهم

رابط يُرسل لأفراد العائلة: يوافق المشارك أولًا، ثم يدخل معلوماته الأساسية (الاسم والجنس والفرع…)، وعند اكتمالها يظهر له اختيار التزامه (الاشتراك الشهري والمدة ومساهمة لمرة واحدة والتطوع والملاحظات)، ويُحفظ كل تعديل مباشرة. يستطيع العودة وتعديل تسجيله أو حذفه. وتراه أنت في المنصة مجمّعًا (العدد، وإجمالي الاشتراك الشهري المعلن، وبحسب الفرع…) ويمكنك تطبيقه على فئات الاشتراك في الخطة المالية.

المنصة نفسها ثابتة بلا خادم، فتُحفظ التسجيلات في **جدول Google Sheets تملكه أنت** عبر خدمة صغيرة (Google Apps Script) شيفرتها في `registration/Code.gs`. الإعداد من داخل المنصة: **القسم 19 ← الإعداد والرابط**، وخطواته:

1. أنشئ جدول Google Sheets جديدًا، ثم **الإضافات ← Apps Script**.
2. الصق محتوى `registration/Code.gs` (زر «نسخ الشيفرة» في المنصة) واحفظ.
3. من **إعدادات المشروع ← خصائص النص البرمجي** أضف `ADMIN_KEY` بقيمة كلمة سر طويلة (12 حرفًا فأكثر).
4. **نشر ← عملية نشر جديدة ← تطبيق ويب**، نفّذ باسم **أنا**، الوصول: **أي شخص**، وانسخ العنوان المنتهي بـ `/exec`. (وعند تعديل الشيفرة لاحقًا: نشر ← إدارة عمليات النشر ← تعديل ← إصدار جديد.)
5. في المنصة: الصق العنوان وكلمة الإدارة، اضبط الخيارات واضغط **نشر إعدادات النموذج**، ثم انسخ الرابط أو اعرض رمز QR.

ما تضمنه الخدمة: القراءة الكاملة لا تتم إلا بكلمة الإدارة؛ يرى المشارك تسجيله وحده برمز سري يُولَّد في متصفحه ولا يُحفظ في الجدول إلا بصمته (SHA-256)؛ لا يُحفظ شيء قبل موافقة المشارك؛ تُرفض البيانات غير الصالحة؛ وتُحفظ الخانات نصًا عاديًا فلا تتحول المدخلات إلى معادلات في الجدول؛ والحد الأقصى 2000 تسجيل. أما **الرابط فعام لمن يملكه**: لا تنشره علنًا، ويمكنك إغلاق التسجيل من المنصة أو حذف أي تسجيل. وتبقى كلمة الإدارة في متصفحك فقط ولا تدخل ملفات المشروع ولا النسخ الاحتياطية.

اختُبر منطق الخدمة بتشغيل `Code.gs` نفسها على محاكاة لخدمات Google (اختبارات الوحدات واختبارات القبول)، أما التشغيل الفعلي على خوادم Google فيعتمد على نشرك أنت له، فجرّبه بتسجيل تجريبي قبل إرسال الرابط للعائلة. بيانات المشاركين شخصية، فاحرص على إتاحة الجدول لأصحاب الصلاحية فقط.

## البيانات والخصوصية

- **كل البيانات تُحفظ في متصفحك فقط** (IndexedDB). لا تُرسل المنصة أي شيء إلى أي خادم، ولا تحتوي على أي أسماء أعضاء أو أرقام هويات أو بيانات مالية حقيقية.
- لا تُنشر بياناتك مع الموقع: ملفات النسخ الاحتياطي وتصديرات المشروع **لا تُرفع إلى المستودع العام**. يمنع `.gitignore` أنماطها المعروفة، ويفشل الأمر `npm run check:privacy` (ويعمل داخل سير النشر) إذا وُجد في المستودع أو في `dist/` أي ملف JSON غير ملفات الإعداد أو ملف تصدير.
- **حدود التخزين المحلي**: مسح بيانات الموقع أو التصفح الخاص أو تغيير المتصفح/الجهاز يُفقد البيانات. النسخ التلقائية داخل المتصفح نفسه، فلا تغني عن **تصدير JSON دوريًا** (قسم «البيانات» أعلى الصفحة ← استيراد وتصدير) وحفظه في مكان آمن خارج المستودع.
- الاستيراد يتحقق من الملف (نوعه وإصداره وسلامة بنيته) ويرفض التالف أو الأحدث من المنصة برسالة واضحة، ثم يضيفه **مشروعًا جديدًا** ولا يكتب فوق مشروع قائم.
- **تسجيلات المشاركين** تُحفظ في جدول Google الخاص بك لا في المنصة ولا في المستودع ولا في ملفات المشروع المصدَّرة (انظر القسم السابق).
- **البيانات التوضيحية** (قسم «البيانات» ← بيانات توضيحية) أرقام افتراضية موسومة بوضوح لتجربة المنصة، ويمكن حذفها بزر واحد؛ وليست أرقام العائلة.

## المرجعية النظامية

يحتوي قسم «مراجعة الميثاق واكتشاف النواقص» قاعدة مرجعية مختصرة تفصل بين ثلاثة أنواع: **متطلب نظامي متحقق منه** (نص قُرئ فعلًا في المصدر بتاريخ الاطلاع المدوّن)، و**اقتراح حوكمي** (ممارسة مقترحة وليست إلزامًا)، و**مسألة تحتاج مراجعة مختص**. المصادر التي قُرئت فعلًا بتاريخ 2026-10-19:

- المركز الوطني لتنمية القطاع غير الربحي — القواعد التنظيمية للصناديق العائلية.
- المركز الوطني لتنمية القطاع غير الربحي — الدليل الاسترشادي للائحة الأساسية للصندوق العائلي.
- المركز الوطني لتنمية القطاع غير الربحي — دليل تسمية الجمعيات والمؤسسات الأهلية والصناديق العائلية والأهلية.
- الهيئة العامة للأوقاف — سجل الأوقاف ولائحة تنظيم أعمال النظارة.

لم تُخترع مواد نظامية ولا أرقام مواد؛ ولا يُذكر رقم مادة إلا إذا ورد في النص المطّلع عليه. الأنظمة تتغير، فتحقق دائمًا من أحدث نص عند الجهة المختصة قبل الاعتماد. وتتضمن المنصة قائمة **مسائل تحتاج مراجعة مختص** (نظامي وشرعي ومالي) في القسم نفسه، يمكن تعليمها منجزة ومتابعتها.

## هيكل المشروع

```
src/types.ts            نموذج بيانات المشروع
src/data/               المتغيرات، مكتبة البنود، الهوية، الأصول والتسميات، المرجعية النظامية، قائمة المتطلبات، البيانات التوضيحية
src/engine/             محرك المحاكاة الشهرية، الحاسبة العكسية، العدالة، المراجعة والتعارضات، نسبة الاكتمال (مع اختباراتها)
src/lib/                المخزن (zustand + immer)، التخزين المحلي، الترحيل والاستيراد، الإجراءات، التنسيق
src/docs/               توليد الوثائق الأربع عشرة والتصدير إلى HTML وMarkdown وDOCX
src/present/            شرائح الشرح المبسط (مصدر واحد للعرض والوثيقة)
src/registration/       عميل خدمة التسجيل وتجميع التسجيلات وقواعد الاكتمال
registration/Code.gs    خدمة التسجيل (Google Apps Script) + harness.mjs لتشغيلها في الاختبارات
src/pages/ components/  الأقسام التسعة عشر وصفحة المشارك والمكونات المشتركة
e2e/acceptance.mjs      اختبارات القبول على Chromium
scripts/check-privacy.mjs   فحص الخصوصية
```

## ملاحظات تصميمية

- استُلهمت بعض أفكار تجربة الاستخدام من الموقع المرجعي المذكور في المتطلبات دون نسخ شيفرته أو هويته أو محتواه، ولا يوجد في هذه المنصة أي رمز دخول.
- الأرقام لاتينية (0-9) عمدًا لسهولة مطابقة الجداول، والتواريخ الهجرية للعرض فقط.
- الخط Cairo مضمّن مع الموقع (لا اتصال خارجي بعد التحميل).
